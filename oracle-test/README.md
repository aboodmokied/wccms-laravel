# تجربة سكربتات Oracle على Oracle XE 11g قبل التسليم

> **تنبيه:** هذه الأدوات لم تُشغَّل بعد (لا Docker ولا Oracle على جهاز التطوير). Docker غير مثبّت على جهاز التطوير الذي كُتبت عليه. شغّلها مرة واحدة على
> جهاز فيه Docker قبل تسليم `wccms_oracle_install.sql`.

هذه الأدوات تشغّل ملفَّي Oracle الخاصين بـ WCCMS على قاعدة **Oracle XE 11.2.0.2** حقيقية داخل Docker.
قاعدة المستشفى الحقيقية تعمل على 11g، فهذا أقرب اختبار ممكن لها.

ما يحدث عند التشغيل، كل مرة من قاعدة فارغة:

1. `01_hos_stub.sql` (بالمستخدم SYSTEM): يحذف المستخدمَين `WCCMS` و `HOS` إن وُجدا، ثم ينشئ مخطط `HOS` مصغّراً.
   فيه جداول المستشفى الثمانية التي يقرأها WCCMS فقط، بأعمدتها المستخدمة ومفاتيحها المركّبة (الرمز, `HOS_NO`) كما في
   القاعدة الحقيقية. فيه مستشفيان (1 و 2) يتشاركان الرموز نفسها:

   | الرمز | المستشفى 1 | المستشفى 2 |
   |---|---|---|
   | الموظف 1001 | موجود | موجود (شخص آخر) |
   | الموظف 1002 | موجود | — |
   | الموظف 2001 | — | موجود |
   | المريض 5001 | موجود | موجود (شخص آخر) |
   | المريض 5002 | — | موجود |

2. `02_wccms_user.sql` (بالمستخدم SYSTEM): ينشئ حساب التطبيق `WCCMS` بأقل ما يحتاجه، أي صلاحيات
   الإنشاء ومساحة تخزين و `SELECT` على جداول HOS الثمانية و `REFERENCES` على جدولي المفاتيح الاختيارية.
   ثم `wccms_oracle_install.sql` (بالمستخدم `WCCMS`): الملف نفسه الذي سيُسلَّم، بلا أي تعديل، لأنه يثبّت في
   الحساب المتصل. ثم `wccms_oracle_uninstall.sql` ثم التثبيت مرة ثانية، للتأكد أن ملف الحذف يترك الحساب
   جاهزاً لإعادة تثبيت نظيفة.
3. `03_smoke_stub.sql` ← `03_smoke_test.sql` (بالمستخدم `WCCMS`، أي صلاحيات التطبيق نفسها): يتحقق أولاً أن WCCMS يقرأ جداول HOS الثمانية وأن الرموز المستخدمة موجودة، ثم يُدخل مستخدماً وطلبَي تحويل، ثم يستدعي
   الإجراءات الأربعة ببيانات XML كما يرسلها التطبيق، ويتحقق من:
   - كل صف أُنشئ يحمل `HOS_NO = 1` (التسجيل، الجروح، التقييمات، الصور، زيارة المراجعة).
   - إعادة إرسال المراجعة بالـ `submission_key` نفسه تُرجع الزيارة نفسها ولا تنشئ صفاً جديداً.
   - موظف موجود في المستشفى 2 فقط يُرفض بـ `INVALID_EMPLOYEE` (ممرض العيادة، وموظف العناية بالجروح أيضاً).
   - قبول طلب سبق قبوله يُرفض بـ `REQUEST_ALREADY_DECIDED`.
   - فك ترميز `&amp; &lt; &gt; &apos; &quot;` والنص العربي، والأرقام العشرية بـ `.` حتى لو كانت الجلسة تستخدم `,`.
   - الفهرس `UX_WC_USERS_EMP`: حساب واحد لكل (موظف, مستشفى)، والحسابات غير المرتبطة بموظف غير محدودة.

   يطبع سطر `PASS` أو `FAIL` لكل فحص، ثم في النهاية `SMOKE TEST: PASS` أو `SMOKE TEST: FAIL`.
   كل ما يُدخله الاختبار يُلغى (ROLLBACK) في النهاية.

## المتطلبات

- Docker Desktop يعمل (على Windows: مع WSL 2). المساحة المطلوبة للصورة نحو 3 GB.
- الاتصال بالإنترنت في أول مرة لتنزيل الصورة `gvenzl/oracle-xe:11`.
- لا تحتاج تثبيت Oracle Client على جهازك: SQL*Plus يعمل داخل الحاوية.

## التشغيل

من مجلد المشروع:

**PowerShell (Windows):**

```powershell
cd oracle-test
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

**bash (Linux، macOS، Git Bash، WSL):**

```bash
cd oracle-test
chmod +x run.sh
./run.sh
```

أول تشغيل ينزّل الصورة ويبدأ القاعدة، وقد يستغرق بضع دقائق. التشغيلات التالية أسرع لأن الحاوية تبقى تعمل.

النتيجة المتوقعة في آخر المخرجات:

```
RESULT: NN passed, 0 failed
SMOKE TEST: PASS

All steps finished without errors.
```

السكربت يتوقف عند أول خطوة تفشل، ويطبع اسم الملف ورمز الخروج. أخطاء الترجمة (compilation errors) لأي
إجراء أو دالة تظهر في جدول في بداية خطوة `03_smoke_test.sql`.

## الفحوص نفسها على قاعدة المستشفى الحقيقية (أثناء التسليم، قبل التشغيل الفعلي)

إن لم يتوفر Docker، أو بعد نجاح العُدّة، شغّل الفحوص نفسها على القاعدة الحقيقية بعد تنفيذ سكربتَي WCCMS عليها.
`live_check.sql` يمرّر لـ `03_smoke_test.sql` رموزاً حقيقية بدل رموز المخطط المصغّر:

```powershell
cd oracle-test
$env:NLS_LANG = 'AMERICAN_AMERICA.AL32UTF8'
sqlplus WCCMS/<كلمة المرور>@//<الخادم>:1521/<service> "@live_check.sql" <HOSPITAL_NO> <EMP_SERIAL لممرض> <MRP_PATREC_CODE لمريض>
```

- `HOSPITAL_NO`: كما في `.env` (يطبعه `wccms:check-hospital`).
- الموظف: أي موظف نشط في هذا المستشفى، **ليس له حساب WCCMS بعد** (يُنشئ الاختبار حساباً مؤقتاً مربوطاً به).
- المريض: أي مريض من هذا المستشفى.

لا يبقى شيء في القاعدة: الإجراءات لا تنفّذ COMMIT أبداً، والسكربت ينتهي بـ ROLLBACK، حتى عند الخطأ. فحصان
يحتاجان مستشفى ثانياً برموز معروفة يعملان على المخطط المصغّر فقط.

النتيجة المطلوبة: `SMOKE TEST: PASS`. أي `FAIL` يوقف التسليم.

## خطوة اختيارية: المفاتيح الأجنبية المركّبة (القسم 8)

القسم 9 في آخر `wccms_oracle_install.sql` مُعطَّل (تعليقات). لتجربته:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -WithForeignKeys
```

```bash
./run.sh --with-fk
```

السكربت ينسخ القسم 9 من الملف نفسه (من أول `ALTER TABLE`)، يحذف `-- ` من أول كل سطر، وينفّذه بالمستخدم `WCCMS` (`build/04_enable_fk.sql`) قبل الاختبار.
بعد الاختبار ينفّذ `05_fk_check.sql`، الذي يتحقق من:

- وجود 14 مفتاحاً أجنبياً إلى `HOS`.
- رفض طلب في المستشفى 1 لمريض موجود في المستشفى 2 فقط (`ORA-02291`)، ورفض موظف من المستشفى 2 في صف للمستشفى 1.
- قبول الصف نفسه عندما يكون `HOS_NO = 2`، وقبول حساب غير مرتبط بموظف.

النتيجة المتوقعة: `FK CHECK: PASS`.

## الإعدادات

متغيرات البيئة (اختيارية؛ القيم الافتراضية للاختبار فقط). كلمات المرور: حروف إنجليزية وأرقام و `_` فقط.

| المتغير | الافتراضي | الاستخدام |
|---|---|---|
| `ORACLE_PASSWORD` | `Oracle_Test_1` | كلمة مرور SYS و SYSTEM في الحاوية |
| `WCCMS_PASSWORD` | `Wccms_Test_1` | كلمة مرور الحساب `WCCMS` الذي ينشئه `02_wccms_user.sql` |

مثال في PowerShell:

```powershell
$env:WCCMS_PASSWORD = 'Another_Pass_9'; .\run.ps1
```

إذا غيّرت `ORACLE_PASSWORD` بعد أول تشغيل، احذف الحاوية أولاً (انظر "الإيقاف والحذف")، لأن كلمة المرور تُضبط
عند إنشائها فقط.

## الاتصال بالقاعدة بعد التشغيل

القاعدة متاحة على `localhost:1521`، الخدمة `XE`:

```bash
docker exec -it wccms-oracle11 sqlplus wccms/Wccms_Test_1@//localhost:1521/XE
```

أو من SQL Developer: المستخدم `WCCMS`، المنفذ 1521، Service name `XE`.

## الإيقاف والحذف

```bash
docker compose down
```

هذا يحذف الحاوية وبياناتها. التشغيل التالي ينشئها من جديد.

## ما لا يختبره هذا

- **ترميز القاعدة:** Oracle XE 11g يعمل بترميز `AL32UTF8`، وقاعدة المستشفى يُفترض أنها `AR8MSWIN1256`.
  العربية تعمل في الحالتين. الفرق: في `AR8MSWIN1256` الحروف خارج Windows-1256 (مثل الرموز التعبيرية) تُحفظ `?`.
  هذا لا يُختبر هنا.
- **DB link:** إذا كان WCCMS في قاعدة أخرى ويقرأ `HOS` عبر DB link، فالمفاتيح الأجنبية في القسم 8 لا تعمل أبداً.
  هذا الاختبار يضع المخططين في القاعدة نفسها.
- **التطبيق نفسه:** الاختبار يستدعي الإجراءات من SQL*Plus مباشرة، لا من Laravel. شكل الـ XML هنا يطابق ما يكتبه
  `OracleClinicalWorkflowGateway::encode()`.
- **أعمدة جداول المستشفى:** المخطط المصغّر فيه الأعمدة التي يستخدمها WCCMS فقط، وأنواعها تقديرية. الإجراءات لا
  تقرأ من المستشفى إلا `HOS.EMPLOYEE_TB (EMP_SERIAL, HOS_NO)`.

## الملفات

| الملف | الوصف |

| `docker-compose.yml` | حاوية `gvenzl/oracle-xe:11` باسم `wccms-oracle11`، والمجلد مركّب في `/kit` |
